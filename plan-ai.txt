PHASE 1: FOUNDATION (ทำก่อนเสมอ)
========================================

1.1 สถานะเอกสาร 5 สถานะ
- enum: draft, pending, approved, reject_return, reject_cancel
- อัปเดต filter ทุกหน้าที่เลือกสถานะได้
- อัปเดต DB schema + API response
- แก้ UI badge สีให้ตรงสถานะ

1.2 ผูกเอกสารกับแผนก
- เพิ่มฟิลด์ department_id ให้ตาราง documents
- อัปเดต API create/edit document รับ department_id
- อัปเดต seed data เอกสารเก่าให้มีแผนก

1.3 ระบบ Permission ใหม่ (RBAC)
- สร้าง permission list:
  - view_scope: "my" | "department" | "all"
  - view_all_sub_departments: boolean (สำหรับหัวหน้า/ผู้อำนวยการ)
- เอาฟังก์ชันพื้นฐานออกจาก permission:
  - dashboard, profile, auditlog = default ทุก role
- อัปเดตหน้า create/edit role UI (tick ช่องใหม่)
- อัปเดต API check permission middleware

PHASE 2: DOCUMENT CENTER (/documents)
========================================

2.1 ตารางเอกสาร
- เพิ่มคอลัมน์: department, created_at
- default sort: created_at DESC

2.2 Filter UI
- Dropdown เลือกแผนก (ดึงจาก master data)
- Dropdown view_scope: My Documents | Department Documents | All Documents
  - ถ้าเลือก All Documents + user มีสิทธิ view_all_sub_departments = true → แสดง dropdown ย่อยเลือกแผนก
- Filter Chips "All Documents" (แสดงทั้งระบบ)
- Filter by Type: ตรวจให้มีแค่ 4 ประเภทจริงในระบบ
- Filter วันที่ (date range)

2.3 API
- GET /documents รองรับ query: department_id, view_scope, date_from, date_to
- logic view_scope:
  - my → where created_by = current_user
  - department → where department_id = current_user.department_id
  - all → where 1=1 (ถ้ามีสิทธิ) หรือ department_id IN (allowed_departments)

PHASE 3: DOCUMENT WORKFLOW
========================================

3.1 แก้บัคสายการอนุมัติ (หน้าสร้างเอกสาร)
- แก้ dropdown เลือกผู้อนุมัติ → ดึงรายชื่อจาก users ที่มี role อนุมัติได้
- แก้สายการอนุมัติแสดงผลไม่ตรง master data:
  - ดึง workflow steps จาก approval_workflows ตาม document_type
  - PR = 3 steps, ตรวจว่า render ครบ

3.2 หน้า Document Review (/documents/:id)
- เพิ่มปุ่ม "แก้ไขเอกสาร" ถ้าสถานะ = draft | pending | reject_return
- เพิ่มปุ่ม "แก้ไขสายการอนุมัติ" (ถ้ายังไม่มีคนอนุมัติ)
- ตรวจ Timeline อนุมัติ:
  - แต่ละ step ต้องตรงกับ approval_logs
  - ถ้าสถานะ step = rejected → บล็อกไม่ให้ลงลายเซ็นต่อ
- ตรวจลายเซ็น:
  - แสดงเฉพาะลายเซ็นของ step ที่ approved แล้ว
  - ถ้าสถานะปฏิเสธ → ซ่อนปุ่มลายเซ็น/ไม่แสดงลายเซ็น

---

PHASE 4: DASHBOARD + REPORTS
========================================

4.1 หน้า Dashboard
- กราฟแท่ง + วงกลม: แสดงตัวเลขบนกราฟเลย (label หรือ data label)
- เพิ่มการ์ด: "เอกสารที่ฉันจัดทำรออนุมัติ" (count where created_by = me AND status = pending)
- Dropdown view_scope เหมือน Document Center
- Filter วันที่
- เอกสารล่าสุด: sort created_at DESC limit 5

4.2 หน้า /admin/reports (ต้องต่างจาก Dashboard)
- Dashboard = real-time KPI
- Reports = deep dive / exportable
- รายงานที่ทำ:
  - สรุปจำนวนเอกสารตามแผนก (table + chart)
  - เวลาเฉลี่ยการอนุมัติ (avg days per approval flow)
  - เอกสาร reject บ่อย (top rejected documents)
  - export CSV/PDF

4.3 หน้า Approvals (/approvals)
- เพิ่ม Filter Chips: "อนุมัติแล้ว" (status = approved)

---

PHASE 5: ADMIN / CONFIG
========================================

5.1 /admin/config/users
- แก้ dropdown ตำแหน่ง → ดึงจาก master data table positions (ไม่ hardcode)
- ตรวจให้ค่าที่ save ลง DB ตรงกับ master data

5.2 Master Data
- permission: เข้าถึงหน้า + CRUD ทุกหัวข้อ

5.3 Audit Log / Profile
- default access ทุก role (ไม่ต้อง tick permission)

SUMMARY: ลำดับสั่ง AI
========================================
1. Phase 1 ให้เสร็จก่อน → ต้องทำทั้งหมดก่อนเริ่ม Phase 2
2. Phase 2 ให้เสร็จก่อน → ค่อย Phase 3, 4, 5
3. Phase 3 (workflow) ทำพร้อม Phase 2 ได้ถ้าไม่ conflict
4. Phase 4 (dashboard) ต้องรอ Phase 2 เสร็จ
5. Phase 5 (admin) ทำท้ายสุด
