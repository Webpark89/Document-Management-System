7. Non-Function requirement  
7.1 ประสิทธิภาพของระบบ (Performance) 
• รองรับผู้ใช้งำนพร้อมกันไม่น้อยกว่ำ 100 Users  
• รองรับกำรค้นหำเอกสำรภำยในเวลำไม่เกิน 3 วินำที  
• รองรับกำรอัปโหลดและดำวน์โหลดไฟล์ PDF ได้อย่ำงมีประสิทธิภำพ  
7.2 ความปลอดภัย (Security) 
• Login ด้วย Username และ Password  
• ก ำหนดสิทธิ ์ ตำม Role  
• เข้ำรหัสข้อมูลระหว่ำงกำรรับส่ง (HTTPS)  
• บันทึก Audit Log ทุกกิจกรรม  
• จ ำกัดสิทธิ ์ กำรเข้ำถึงเอกสำรตำมผู้ใช้งำน  
7.3 ความพร้อมใช้งาน (Availability) 
• ระบบรองรับกำรใช้งำนภำยในองค์กร (On-Premise)  
• รองรับกำรใช้งำนผ่ำน Web Browser  
• รองรับกำรใช้งำนทุกฝ่ำยในองค์กร  
7.4 ความสามารถในการขยายระบบ (Scalability) 
• รองรับกำรเพิ่มจ ำนวนผู้ใช้งำนในอนำคต  
• รองรับกำรเพิ่มประเภทเอกสำร  
• รองรับกำรเพิ่ม Workflow กำรอนุมัติ  
• รองรับกำรเพิ่ม Dashboard และรำยงำน  
7.5 การส ารองข้อมูล (Backup) 
• ส ำรองฐำนข้อมูลตำมรอบเวลำที่ก ำหนด  
• ส ำรองไฟล์เอกสำร  
• รองรับกำรกู้คืนข้อมูล (Restore) \n\n=== PAGE 8 ===\n8. UX / UI Design  
- รองรับกำรใช้งำนทั้งบนเดสก์ท็อปและมือถือ 
- กำรออกแบบ UX : 
กำรวิจัยและวิเครำะห์ผู้ใช้: วิเครำะห์ข้อมูลผู้ใช้เพื่อท ำควำมเข้ำใจพฤติกรรม 
สถำปัตยกรรมข้อมูล: จัดระเบียบข้อมูลในรูปแบบที่ใช้งำนง่ำยและเข้ำใจได้ 
ผังกำรใช้งำน: สร้ำงเส้นทำงกำรใช้งำนเพื่อให้ผู้ใช้ได้รับประสบกำรณ์ที่รำบรื่น 
กำรร่ำงโครงร่ำง: ร่ำงโครงสร้ำงหน้ำจออย่ำงง่ำยส ำหรับกำรทดสอบ 
กำรสร้ำงต้นแบบ: สร้ำงต้นแบบที่สำมำรถคลิกได้ส ำหรับกำรทดสอบกำรใช้งำนจริง 
กำรทดสอบผู้ใช้: ทดสอบต้นแบบกับผู้ใช้จริง 
- กำรออกแบบ UI : 
กำรออกแบบภำพ: ออกแบบรูปลักษณ์ สี ฟอนต์ และเค้ำโครง 
กำรออกแบบส่วนประกอบ: ออกแบบส่วนประกอบต่ำงๆ เช่น ปุ่ม ไอคอน และรูปภำพ 
ควำมสม ่ำเสมอ: ออกแบบผลิตภัณฑ์ให้สม ่ำเสมอเพื่อสร้ำงควำมคุ้นเคย 
**ข้อก ำหนดกำรแก้ไข UX/UI : อนุญำตให้แก้ไขได้ไม่เกิน 3 ครั้งเพื่อให้เป็นไปตำมก ำหนดเวลำ
ของโครงกำร**
